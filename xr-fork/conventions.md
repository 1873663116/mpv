# Enchron mpv fork — 约定与术语

本文件是这个 fork 自己的命名约定与术语表,独立于上游 mpv。
目的:消除歧义(例如不要再把新功能含糊地叫"截图功能的变体")。

## 术语表(概念 / 功能 / 文档用词)

| 术语 | 英文标识 | 含义 |
|---|---|---|
| **常驻纹理出口** | `resident_texture` | 我们新增的功能:让 `vo_gpu_next` 把渲染好的视频帧输出到一张**常驻的、可被外部取用的纹理**(阶段 1 起为 IOSurface-backed)。口语/比喻可叫"常驻画板"。**不要**叫它"截图变体"。 |
| **屏幕出口** | `draw_frame` | 上游原有的直出路径:渲染到 swapchain 画布并 `submit_frame` 呈现上屏。窗口模式走这条,我们不改。 |
| **常驻画板 / 离屏纹理** | — | "常驻纹理出口"产出的那张纹理本身。 |
| **句柄** | — | 指向纹理/IOSurface 的引用(`MTLTexture` 引用、`IOSurfaceRef`、指针),用于把内部纹理交给外部 Swift/RealityKit。 |

## 命名约定

- **代码符号**:跟随 mpv 既有风格(snake_case)。我们**新增的、对外可见**的符号(函数、选项)加
  `xr_` 前缀(如 `xr_resident_texture_render`),便于和上游符号区分、rebase 时一眼认出我们的改动。
  内部 static 符号不强制前缀,跟随 mpv。
- **文件 / 目录**:我们自己的文件只放 `xr-fork/`,文件名用 kebab-case(如 `0001-xxx.md`)。
- **文档 / 对话用词**:统一使用上方术语表的中文词,避免随口造词造成歧义。

## 维护

新增功能或概念时,先在此表登记术语,再在代码/文档中使用。
